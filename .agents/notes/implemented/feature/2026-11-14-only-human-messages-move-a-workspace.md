# Agent Note: 只有人类消息和新会话算活动

Status: implemented

## Problem

「最近用过的工作区」听起来简单，但一个工作区里随时可能发生不是用户发起的动静：智能体在后台跑工具、
会话被归档、子智能体在父会话里被派出去干活。如果这些都算「用过」，列表就会在用户什么都没做的时候
自己跳——最坏的情况是最上面的工作区里看不到任何最近的对话。

## Decision

活动只有两种来源，都由宿主的事件/接口给出：

- **人类消息**：宿主事件 `api-session/activity`。它只在消息的 `source.kind === 'user'` 时触发，
  所以智能体自己写日志、跑工具都不会惊动它。时间戳用事件带的那一个，不看本地时钟。
- **新会话**：`api-session/added`，含还没发言的空会话——「我刚开了个新会话」也是「我刚用过这个
  工作区」。这一条可以在配置里关掉（`trackNewSessions`）。

三种会话明确不算：

- **子智能体的会话**（`origin === 'subagent'`）：它归属于父会话，父会话动过就够了。
- **已归档会话**：注册表的 `archivedSessionIds` 里的会话，历史时间不参与排名。否则归档之后工作区
  还赖在最前面，用户已经看不到任何近期会话。
- **不属于任何工作区的会话**：注册表里没有任何工作区认领它（`isGrouped()`），它挪不动任何东西。

启动时按 `sessionController.list()` 把已有会话过一次（`sortOnStart`），这样刚装插件的机器不必等到
下一次发言才有顺序。

## Alternatives considered

**按会话文件的修改时间排。** 那等于把「智能体写了日志」也算成活动，后台任务会让列表持续跳动；而且
插件得去读会话库，把一件只依赖事件的事变成文件系统依赖。

**按工作区目录的 mtime 排。** 与插件无关的任何东西（编辑器、日志、临时文件）都会改它。

**归档会话也参与排名。** 用户看不到那些会话，顺序却由它们决定，等于让一部分看不见的历史压住看得见的
现在。

**把「打开会话」也算活动。** 宿主没有给插件「用户打开了某个会话」这个事件；能拿到的最接近的东西是
活动事件，而它已经覆盖了「真的说了话」这一半。

## Consequences

- 后台跑很久的任务不会改变工作区顺序，用户不会在自己没动手时看到列表跳动。
- 代价：只看不发言的会话不算活动。这与「最近用过」的直觉一致，写进了 README 的「什么算活动」。
- 事件带的时间戳与本机时钟无关，所以时钟漂移、跨设备的时间差都不会把顺序排乱；过时的时间戳会被
  `record()` 直接忽略（`test/order.test.ts` 的「过时的时间戳与未分组会话不会触发重排」）。
