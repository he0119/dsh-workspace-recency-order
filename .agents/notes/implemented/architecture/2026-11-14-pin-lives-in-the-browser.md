# Agent Note: 固定列表只存在浏览器里，由页面维持

Status: implemented

## Problem

「把这个工作区固定在最前面」需要一份「我固定了谁」的记录。宿主只提供会话级的固定，工作区级没有对应
字段；注册表那份顺序里也不带「这一条是不是用户钉的」这种标记。

那么这份记录放哪里？放宿主就得给持久注册表加字段或加一份自己的存储，还要在每一次宿主重排之后与它
对账；放浏览器就只有本页知道，但页面关掉就没人维持。

## Decision

固定列表存在**当前浏览器**的 `localStorage` 里，键是
`dsh.workspace-recency.pinned-workspaces.v1`，值是一个字符串数组，最近固定的在前
（见 [formats.md](../../../../docs/formats.md)）。

顺序本身仍然写在宿主注册表上：固定只是「页面看到宿主把固定项挤下去之后，把它挪回来」。谁在维持？
打开着的页面。多个页面共享同一份 `localStorage`，所以它们对「固定了谁」有一致看法，只在写顺序时
可能互相抢（处理见[多页面抢同一个顺序时让位](2026-11-14-yield-to-the-other-page.md)）。

切换固定是一个事务：先写 `localStorage`，再挪顺序；挪失败就把 `localStorage` 写回原样，并且只提
一次失败（`FAILURE_NOTICE_GAP_MS`，30 秒）。存不进去（隐私模式、站点数据被禁）就直接说「固定无法
记住」，不假装成功。

## Alternatives considered

**在宿主注册表里加工作区固定字段。** 那是宿主的数据格式，插件改它就是在赌下一版宿主的形状；而且这份
记录是**某个浏览器**的偏好，写进跨设备同步的宿主存储，等于把一台机器的选择推给所有机器。

**固定顺序也完全交给宿主。** 宿主没有「钉住」的概念，插件要自己发明一份顺序并持续覆盖它；一旦页面
不在，宿主的下一次活动就会把它挤下去——这正是「固定靠页面维持」要说明的边界。

**固定项不在快照完整时清理。** 加载中或断线时的快照不代表工作区被删了，照它清理会把用户真金白银
固定过的工作区悄悄抹掉。这条在 `src/client/index.ts` 的 `settled()` 上，测试
（`test/client.test.mjs` 的「已删除工作区的固定项会被清理（只在快照完整时）」）盯着它。

## Consequences

- 换设备、换浏览器、清站点数据之后要重新固定：README 的「取舍与限制」里写明了。
- 页面关掉期间没人纠正，别处的活动仍可能把固定项挤下去；下次打开页面会自动挪回最前。
- `localStorage` 里是纯 id 数组，没有时间戳与版本以外的元数据；键名里的 `.v1` 是给将来换格式留的
  断点。
