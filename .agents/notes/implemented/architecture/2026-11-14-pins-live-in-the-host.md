# Agent Note: 固定列表交给宿主，页面不再纠正顺序

Status: implemented

## Problem

「把某个工作区固定在最前」需要两样东西：一份「固定了谁」的列表，和一个「谁负责让顺序保持住」的
答案。宿主只提供工作区的持久顺序，没有固定字段；页面能看到顺序，但每次写顺序都要经过宿主，而宿主
自己也会按活跃度重排。

把列表放在浏览器、由打开的页面在每次宿主重排之后把固定项挪回去，会有一个看得见的结果：在别的工作区
发一次消息，固定项先被挤下去、几百毫秒后再弹回来；固定第二个工作区时，固定的那两行会互相穿过去。
根子是同一个顺序上有两个写手——宿主按活跃度写一次，页面再按固定写一次，双方互不知道对方；而宿主
一次只能挪一行，纠正多个固定项就要写好几遍。

## Decision

固定列表归宿主：存在 `<DSH_HOME>/workspace-recency-order/pins.json`，排序时把固定项整体放在开头
（`orderByActivity()` 的 `pinned` 参数），其余工作区按活跃度排在后面。

页面不再碰顺序。它只在三个时刻读写列表：加载时读一次、点菜单时发一条切换命令、切回窗口时再读一次。
读写走宿主 `ctx.connection.fetch.register()` 注册的认证路由 `GET/POST /api/workspace-recency/pins`，
只对通过浏览器登录校验、身份是 owner 的会话开放；宿主负责过滤未知 id、落盘、重排，然后把当前那份
列表回答给页面。

命令带的是目标状态（`{ workspaceId, pinned }`），不是整份列表：重复发送、两个页面同时点都不会把对方
的状态覆盖掉；状态没变时不写盘、不重排。两端共用 `src/protocol.ts` 里那一份形状。

于是顺序只有一个写手。一次活动只产生一次移动：新活跃的工作区移到固定组下面，固定组一动不动；固定
一个新工作区也只移动那一行，组里已有的行不动。取消固定时宿主按活跃度把它放回该在的位置。

## Alternatives considered

**固定列表只存在浏览器，页面按快照纠正。** 这是本插件最早的做法：列表在 `localStorage`，页面看到
宿主把固定项挤下去就挪回来，多页面互相顶时让位 30 秒。落选的原因是它必然产生「下掉再弹回」：页面
只能事后纠正，而纠正要经过宿主，至少要重画两次。

**让页面当唯一的排序者，宿主排序停用。** 能去掉两个写手，但页面关掉期间顺序不动，多个页面的顺序
会互相覆盖；页面也拿不到完整的会话活跃时间，排出来会比宿主那份粗。

**不从顺序上表达固定（只做视觉标记或顶部快捷入口）。** 不需要写顺序，但「固定」就不再是「排在最
前」，与这个插件的用途冲突。

**把固定列表放进宿主的 Cordis 配置。** 配置文件是部署结构，不是运行时开关；从浏览器改它要经过设置
服务和 profile 重载，切一次固定会重启插件。落选。

## Consequences

- 固定在整台机器（同一个 `DSH_HOME`）上共享：桌面和手机连同一个宿主时看到同一份固定列表，不再
  各管各的。
- 页面关掉期间固定照样生效；删掉 `pins.json` 就回到没有固定，宿主下次启动读到空列表。
- 宿主读完 `pins.json` 才开始按活跃度排序，所以启动后第一轮排序会晚一个文件读取的时间。
- 固定组内的顺序跟着列表当前的样子走：新固定的进组尾，组内拖动有效；想让某一行离开组，得取消固定。
- 没有 `connection` 服务的宿主（非 Web GUI）注册不了路由，页面那一半也不会加载：固定只在 Web GUI
  里有意义。
