# 界面与文案规格

本插件的界面只有一处：工作区行「…」菜单里的一项。除此之外它不改任何视觉——侧边栏的顺序、行高、
图标都由宿主决定。

## 菜单项

| 项 | 值 |
| --- | --- |
| 目标 | 工作区的「…」菜单（`contextMenus.register({ target: 'workspace' })`），右键该行也能打开 |
| 注册 id | `workspace-recency.pin` |
| 位于 | `order: 50`（宿主自己那几项之间） |
| 条目 id | `pin` |
| 条目数 | 恒定一条：已固定显示「取消」，未固定显示「固定」，不并列两条 |

文案（中文 / 英文，键见 [formats.md](formats.md#语言键)）：

- 未固定：`固定工作区到最前` / `Keep workspace at top`
- 已固定：`取消工作区固定` / `Stop keeping workspace at top`

**权限**：拿得到 `remoteAccess` 服务、且它对 `('workspace', id, 'workspace/insertBefore')` 明确说
`false` 时，这一项**不出现**（`resolve()` 返回空数组）。拿不到权限面时按允许处理——那是「这个连接
本来就没有权限服务」，不是「它拒绝了」。

## 图标

菜单项的图标走 `contextMenu.icon` 插槽，两个 key 各注册一次：
`workspace-recency.pin`、`workspace-recency.unpin`。

- 16×16 的 SVG 图钉，`stroke="currentColor"`、宽 1.3、圆头圆角；未固定只有描边，已固定加一层
  `fill="currentColor"` 与 `fill-opacity="0.22"`。
- 只用 `currentColor`，不写死颜色：主题切换时它自己跟着变。
- `aria-hidden="true"`：菜单项的文字已经说明了动作，图标不重复播报。

## 提示

提示走宿主的 `contextMenus.notify(text, success)`——不自己画 toast。

| 时机 | 文案（中） | success |
| --- | --- | --- |
| 固定成功 | 已固定：这个工作区会一直排在最前，再点同一项可取消 | `true` |
| 取消固定 | 已取消固定 | `true` |
| 移动失败 | 调整工作区顺序失败 | `false` |
| 存储不可用 | 这个浏览器不允许保存设置，固定无法记住 | `false` |
| 检测到别的页面 | 检测到另一个页面也在调整工作区顺序，暂时停止固定 30 秒 | `false` |

节流：`failed` 与 `yielding` 都按「同类 30 秒内只提示一次」处理，避免一直被拒时刷屏。

## 顺序的表现

- 固定的工作区排在列表最前面，多个固定项之间按**最近固定的在前**。
- 取消固定后这个工作区立刻回到活跃度顺序里它该在的位置（不留在顶端等下一次活动）。
- 宿主把固定项挤下去之后，页面在 600 毫秒内把它挪回；用户看到的是列表「弹回」，不是停在错误位置。
- 让位那 30 秒里固定项可能被挤下去且**不会**被挪回——这是设计，提示语已经说明「暂时停止固定」。

## 明确不做的事

- **不在工作区行上画按钮。** 工作区行只留了「…」菜单这一个扩展位（会话行才有悬停按钮的插槽）；要
  在行上画自己的图标只能整体替换 `sidebar.workspaces`，那会丢搜索、拖动排序、工作区树与各种对话框。
- **不改工作区行的顺序动画。** 顺序由宿主快照驱动，插件只写注册表；自己插动画会让「列表在动」和
  「宿主说它在哪」两件事打架。

## 验收

在真实页面上逐条看：

1. 工作区行的「…」菜单里有「固定工作区到最前」，图标是一枚描边图钉。
2. 点它之后该工作区跳到第一位，提示「已固定…」，再打开同一个菜单显示「取消工作区固定」、图标是实心
   图钉。
3. 在别的工作区里发一条消息：固定项仍然在第一位。
4. 点「取消工作区固定」：它回到按活跃度该在的位置，提示「已取消固定」。
5. 同时开两个页面，各固定不同工作区：其中一个会在几秒后提示「暂时停止固定 30 秒」，之后自己恢复。
6. 控制台没有 `slot entry crashed`、没有重复注册报错。
