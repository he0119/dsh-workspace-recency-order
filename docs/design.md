# 界面与文案规格

本插件的界面只有一处：工作区行「…」菜单里的一项。除此之外它不改任何视觉——侧边栏的顺序、行高、
图标都由宿主决定。

## 菜单项

| 项 | 值 |
| --- | --- |
| 目标 | 工作区的「…」菜单（`contextMenus.register({ target: 'workspace' })`），右键该行也能打开 |
| 注册 id | `workspace-recency.pin` |
| 位于 | `order: 50`（宿主自己那几项之间） |
| 条目 id | `pin` |
| 条目数 | 恒定一条：已置顶显示「取消置顶」，未置顶显示「置顶」，不并列两条 |

文案（中文 / 英文，键见 [formats.md](formats.md#语言键)）：

- 未置顶：`置顶` / `Pin`
- 已置顶：`取消置顶` / `Unpin`

**权限**：拿得到 `remoteAccess` 服务、且它对 `('workspace', id, 'workspace/insertBefore')` 明确说
`false` 时，这一项**不出现**（`resolve()` 返回空数组）。拿不到权限面时按允许处理——那是「这个连接
本来就没有权限服务」，不是「它拒绝了」。

## 图标

菜单项的图标走 `contextMenu.icon` 插槽，两个 key 各注册一次：
`workspace-recency.pin`、`workspace-recency.unpin`。

- 16×16 的 SVG 图钉，`stroke="currentColor"`、宽 1.3、圆头圆角；未置顶只有描边，已置顶加一层
  `fill="currentColor"` 与 `fill-opacity="0.22"`。
- 只用 `currentColor`，不写死颜色：主题切换时它自己跟着变。
- `aria-hidden="true"`：菜单项的文字已经说明了动作，图标不重复播报。

## 提示

提示走宿主的 `contextMenus.notify(text, success)`——不自己画 toast。

| 时机 | 文案（中） | success |
| --- | --- | --- |
| 置顶成功 | 已置顶 | `true` |
| 取消置顶 | 已取消置顶 | `true` |
| 读写置顶列表失败 | 调整工作区顺序失败 | `false` |

节流：`failed` 按「30 秒内只提示一次」处理，避免宿主持续拒绝时刷屏。

## 顺序的表现

- 置顶的工作区整体占列表开头一段；**组内同样按最近消息排**：刚用过的置顶工作区排在这一组最前面。
- 在别的工作区发消息：那个工作区移到置顶组**下面**，置顶组一步不动——不会出现「置顶项下掉再弹回」。
- 取消置顶后这个工作区立刻回到活跃度顺序里它该在的位置（不留在顶端等下一次活动）。
- 页面不参与挪动顺序：它只在加载、切换置顶、切回窗口或网络恢复时读写宿主那份置顶列表；页面关掉期间置顶照样生效。

## 明确不做的事

- **不在工作区行上画按钮。** 工作区行只留了「…」菜单这一个扩展位（会话行才有悬停按钮的插槽）；要
  在行上画自己的图标只能整体替换 `sidebar.workspaces`，那会丢搜索、拖动排序、工作区树与各种对话框。
- **不改工作区行的顺序动画。** 顺序由宿主快照驱动，插件只写注册表；自己插动画会让「列表在动」和
  「宿主说它在哪」两件事打架。

## 验收

在真实页面上逐条看：

1. 工作区行的「…」菜单里有「置顶」，图标是一枚描边图钉。
2. 点它之后该工作区跳到第一位，提示「已置顶」，再打开同一个菜单显示「取消置顶」、图标是实心
   图钉。
3. 在别的工作区里发一条消息：那个工作区排到置顶组下面，置顶组不动；不会看到置顶项先下去再弹回。
4. 置顶第二个工作区：它按最近消息落到置顶组里的位置；在原来的置顶工作区里发消息，它会回到组内最前。
5. 点「取消置顶」：它立刻回到按活跃度该在的位置，提示「已取消置顶」。
6. 刷新页面：置顶项仍在开头，菜单仍显示「取消置顶」；`$DSH_HOME/workspace-recency-order/pins.json` 里是这份列表。
7. 控制台没有 `slot entry crashed`、没有重复注册报错。
